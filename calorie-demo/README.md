# Multi-LLM orchestration demo: calorie tracker

Claude Code orchestrates two other LLMs through their APIs:

| Role | Model (provider) | Why |
|---|---|---|
| Orchestrator, spec author, integrator, reviewer | Claude (Claude Code) | Owns the contract and verifies the result |
| Backend (FastAPI + SQLite + tests) | Claude (Claude Code, written directly) | OpenAI account had no credits (`insufficient_quota`), so the backend was not built via the API. `orchestrator/` can still run it with `run backend` once credits exist (overwrites `backend/`). |
| Frontend (single-file HTML/JS) | Gemini (`gemini`) | Frontend role |

## Layout
- `docs/API_SPEC.md`: the contract both models build against
- `prompts/`: the exact prompts sent (`{{API_SPEC}}` is injected at run time)
- `orchestrator/`: `orchestrate.py` (stages, parsing, logging), `config.json` (provider/model per stage), `pricing.json`
- `logs/orchestration.jsonl`: one line per model call (tokens, latency, cost, status)
- `logs/responses/`: raw model replies
- `logs/COST_REPORT.md`: generated by `python orchestrator/orchestrate.py report`
- `backend/`, `frontend/`: the generated app

## Setup (environment settings, not chat)
1. Environment variables: `GEMINI_API_KEY`, `OPENAI_API_KEY`.
2. Network: allow `generativelanguage.googleapis.com` and `api.openai.com` (Custom → Allowed domains).
3. `pip install -r backend/requirements.txt requests`

## Run
```
python orchestrator/orchestrate.py models        # pick the backend model, set it in config.json
python orchestrator/orchestrate.py run backend
python orchestrator/orchestrate.py run frontend
cd backend && pytest && uvicorn main:app --port 8000
python orchestrator/orchestrate.py report
```
Pricing in `orchestrator/pricing.json` must be filled from the providers' official pages; until then the report shows tokens and `n/a` for cost.
